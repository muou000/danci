# 按内容用途拆分短文资源并分层加载

为减少首屏网络请求与内存占用，短文语料按用途拆成三类静态资源：首篇编译正文随应用入口加载；短文目录元数据（篇号、题材、标题、目标词条键）单独提供，用于目录筛选与阅读进度展示；每篇其余正文作为独立 JSON 资源，仅在打开、翻页或邻篇空闲预取时加载。全局查词与“已掌握词库”共用构建期生成的查词索引，仅在用户发起查词或打开词库时加载。

应用通过 `PassageContentRepository` 这一接口取得目录、单篇正文和查词索引。默认适配器使用 Vite 生成的静态 URL，测试适配器可在内存中提供相同接口。加载器按短文 ID 共享进行中的请求并缓存已取得正文；批量图片导出是明确的全库操作，才会请求全部正文。

这样保留纯前端、离线可部署的静态架构，同时把首屏阅读、目录浏览、单篇精读、全局检索和批量导出分别绑定到实际需要的数据粒度。新增短文时，构建脚本必须同时生成独立正文、目录条目和查词索引。
